# Челлендж 100 дней — автономная версия

Приложение для отслеживания 100-дневного тренировочного челленджа.
Вытащено из артефакта Claude и отвязано от платформы: теперь работает
где угодно, данные хранятся в браузере (localStorage).

## Файлы

- `index.html` — само приложение (весь UI + логика, один файл)
- `data.json` — программа на 100 дней и библиотека из 158 движений (только чтение)
- `README.md` — этот файл

## Как запустить

Приложение грузит `data.json` через `fetch`, поэтому **просто открыть
index.html двойным кликом не выйдет** — браузер заблокирует fetch с file://.
Нужен локальный сервер. Любой из вариантов:

```bash
# Python (есть почти везде)
cd challenge-app
python3 -m http.server 8000
# открыть http://localhost:8000

# или Node
npx serve
```

Для телефона: подними сервер на компе, зайди с телефона по IP компа
(`http://192.168.x.x:8000`), пока оба в одной сети. Либо задеплой статику
куда угодно (Netlify, Vercel, GitHub Pages, свой nginx).

## Как устроены данные

**Не меняется (data.json):**
- `days` — 100 дней. У каждого: `title`, `payload` (основная тренировка),
  `variant` (облегчённый вариант на замену). Внутри payload — `blocks`,
  в каждом блоке `items` с полями `movement` (код), `text` (подходы×повторы,
  вес), `note`.
- `moves` — 158 движений по коду. Поля: `name_ru`, `cue` (техника),
  `equipment`, `category`, `unlock_day`, `media_url`.

**Меняется, лежит в localStorage под ключом `challenge100`:**
- `state` — `started_on`, `swaps_left` (замены, старт 3), `dayoff_left`
  (отгулы, старт 1), `bench_max`, `status`.
- `logs` — по каждому закрытому дню: `outcome` (`done`/`swap`/`dayoff`/`open`),
  `items` (индексы отмеченных пунктов), `note`.

## Логика (важно)

- **Текущий день = первый незакрытый**, не по календарю. Пока день не
  закрыт, он остаётся активным, даже если по датам уже прошло больше.
- День закрывается кнопкой «Закрыть день». Она активна только когда
  отмечены **все** пункты (в дне 1 их 12).
- Закрыл → следующий открывается сразу.
- Стрелки ← → листают между днями. Назад к закрытым можно, вперёд
  дальше текущего — нет.

Это ответ на баг «не открывается следующий день»: в исходной базе день 1
висел со статусом `open` и одной отмеченной галочкой из 12. Приложение
работало правильно — день просто не был закрыт.

## Что стоит доделать (backlog)

1. **Пуш-напоминание в 7 утра.** Сейчас нет. Варианты: PWA + Notification
   API (сработает только когда вкладка живёт), или отдельный телеграм-бот
   рядом, который читает тот же data.json и пингует по расписанию.
2. **Медиа к движениям.** Сейчас `media_url` — это ссылка на поиск в
   YouTube, не на конкретное видео. Заменить на прямые ссылки или свои ролики.
3. **Экспорт/импорт прогресса.** localStorage привязан к браузеру.
   Добавить кнопку «выгрузить logs в файл» и «загрузить», чтобы переносить
   между устройствами. Пара функций на JSON.blob.
4. **Дни 29–100 — черновые веса.** Проставлены генератором наперёд.
   После первого 14-дневного цикла пересчитать по реальным результатам.
5. **Замеры и прогресс-графики.** Вкладка «Прогресс» есть, но данные
   замеров (вес, талия, обхваты) пока никуда не пишутся — добавить форму.

## Как пересобрать data.json

Если менял программу генератором (`gen_v2.py`) — пересобери data.json
из выгрузки. Структура: `{state, days:{"1":{...}}, moves:{"code":{...}}, logs:{}}`.
Веса и дни правятся прямо в JSON, приложение подхватит при перезагрузке.
